# スプリント計画ガイド

## 概要

スプリント計画は、スプリントで何を達成するかを決定するセレモニーです。

## フロー

```
┌─────────────────────────────────────────────────────────────────────┐
│                      SPRINT PLANNING                                │
├─────────────────────────────────────────────────────────────────────┤
│                                                                     │
│  1. ゴール設定                                                      │
│     「このスプリントで達成したいことは何か？」                      │
│                            ↓                                        │
│  2. バックログ選択                                                  │
│     Product Backlogから優先度の高いストーリーを選択                 │
│                            ↓                                        │
│  3. タスク分解                                                      │
│     各ストーリーを具体的なタスクに分解                              │
│                            ↓                                        │
│  4. 見積もり                                                        │
│     各タスクの工数を見積もり                                        │
│                            ↓                                        │
│  5. コミット                                                        │
│     チームがスプリントバックログにコミット                          │
│                                                                     │
└─────────────────────────────────────────────────────────────────────┘
```

## 1. スプリントゴール設定

スプリントで達成したい目標を1文で表現。

```markdown
## Sprint 1 Goal
「ユーザーが新規登録してログインできるようにする」

## Sprint 2 Goal
「ユーザーがプロフィールを編集し、設定を保存できるようにする」
```

## 2. バックログ選択

### 選択基準

1. **優先度**: Product Ownerが設定した優先度
2. **依存関係**: 他のストーリーへの依存
3. **キャパシティ**: チームの処理能力

### ベロシティ

過去のスプリントで完了したポイント数を参考に、今回のスプリントで取り組める量を判断。

```
Sprint 1: 13pt 完了
Sprint 2: 15pt 完了
Sprint 3: 14pt 完了
→ 平均ベロシティ: 14pt
→ Sprint 4 では約14ptを目標
```

## 3. タスク分解

各ユーザーストーリーを、TDDサイクルで実装可能な粒度に分解。

### 分解例

```markdown
## US-1: ユーザー登録機能

### Acceptance Criteria
- メールアドレスとパスワードで登録できる
- パスワードは8文字以上
- 重複メールアドレスはエラー
- 登録成功時に確認メール送信

### タスク分解（TDD対応）
1. [ ] ユーザーモデルの設計・ドキュメント作成
2. [ ] メールバリデーションのテスト作成 (RED)
3. [ ] メールバリデーションの実装 (GREEN)
4. [ ] パスワードバリデーションのテスト作成 (RED)
5. [ ] パスワードバリデーションの実装 (GREEN)
6. [ ] 重複チェックのテスト作成 (RED)
7. [ ] 重複チェックの実装 (GREEN)
8. [ ] 登録APIのテスト作成 (RED)
9. [ ] 登録APIの実装 (GREEN)
10. [ ] メール送信のテスト作成 (RED)
11. [ ] メール送信の実装 (GREEN)
12. [ ] リファクタリング (REFACTOR)
13. [ ] E2Eテストの作成
```

## 4. 見積もり

### ストーリーポイント

相対的な複雑さ・工数を表す単位。フィボナッチ数列を使用。

```
1pt: 非常に簡単（数時間）
2pt: 簡単（半日〜1日）
3pt: 普通（1-2日）
5pt: やや複雑（2-3日）
8pt: 複雑（3-5日）
13pt: 非常に複雑（要分割検討）
```

### プランニングポーカー

チームメンバーが同時に見積もりを出し、差異があれば議論。

## 5. Sprint Backlog完成

```markdown
# Sprint 3 Backlog

## Sprint Goal
「ユーザーが新規登録してログインできるようにする」

## Selected User Stories

### US-1: ユーザー登録機能 (5pt)
| ID | タスク | 担当 | 状態 |
|----|--------|------|------|
| 1.1 | ユーザーモデル設計 | Claude | Done |
| 1.2 | バリデーションテスト | Claude | In Progress |
| 1.3 | バリデーション実装 | Claude | TODO |
| ... | ... | ... | ... |

### US-2: ログイン機能 (3pt)
| ID | タスク | 担当 | 状態 |
|----|--------|------|------|
| 2.1 | 認証ロジックテスト | Claude | TODO |
| 2.2 | 認証ロジック実装 | Claude | TODO |
| ... | ... | ... | ... |

## Total: 8pt (ベロシティ14pt内)
```

## Claude Codeでの実践

ユーザーからリクエストを受けた時：

```markdown
1. ユーザーストーリーを理解
   - 「何を達成したいか」を確認
   - 不明点は質問

2. Acceptance Criteriaを確認
   - 完了条件を明確化
   - テストケースの元になる

3. タスク分解
   - TodoWriteツールでタスクリスト作成
   - TDDサイクルを意識した粒度

4. 見積もり（オプション）
   - 複雑さに応じて作業順序を決定

5. 実装開始
   - 1タスクずつTDDで実装
   - 完了したらTodoをupdateして次へ
```

## チェックリスト

- [ ] スプリントゴールが明確か
- [ ] 選択したストーリーがベロシティ内か
- [ ] 全ストーリーにAcceptance Criteriaがあるか
- [ ] タスクがTDD実装可能な粒度か
- [ ] 依存関係が整理されているか
