# スクラムワークフロー

このプロジェクトでは、スクラムフレームワークを採用し、TDDとQuality Gateを統合しています。

## スクラムの基本

```
┌─────────────────────────────────────────────────────────────────────┐
│                         SCRUM FRAMEWORK                             │
├─────────────────────────────────────────────────────────────────────┤
│                                                                     │
│  Product      Sprint       Daily         Sprint       Sprint        │
│  Backlog  →  Planning  →  Standup   →   Review   →  Retro          │
│     │           │           │             │           │             │
│     ↓           ↓           ↓             ↓           ↓             │
│  優先順位     タスク      進捗確認       デモ        改善           │
│  付け        選択・       障害共有      フィード     アクション     │
│             見積もり                    バック                      │
│                                                                     │
│  ←────────────── Sprint (1-2週間) ──────────────→                  │
│                                                                     │
└─────────────────────────────────────────────────────────────────────┘
```

## ロール

### Product Owner（人間）
- プロダクトバックログの管理
- ユーザーストーリーの作成と優先順位付け
- 受け入れ条件の定義

### Development Team（Claude + 人間）
- スプリントバックログの実装
- TDDによる開発
- Quality Gateの通過

### Scrum Master（人間）
- スクラムプロセスの促進
- 障害の除去
- チームの改善支援

## アーティファクト

### 1. Product Backlog

ユーザーストーリーのリスト。優先順位順に並べる。

```markdown
| ID | ユーザーストーリー | 優先度 | 見積もり |
|----|-------------------|--------|---------|
| 1  | ユーザー登録機能   | High   | 5pt     |
| 2  | ログイン機能       | High   | 3pt     |
| 3  | プロフィール編集   | Medium | 3pt     |
```

### 2. Sprint Backlog

スプリントで実装するユーザーストーリーとタスク。

```markdown
## Sprint 1 Backlog

### US-1: ユーザー登録機能
- [ ] ユーザーモデル設計
- [ ] バリデーションテスト作成
- [ ] ユーザーモデル実装
- [ ] 登録APIテスト作成
- [ ] 登録API実装
- [ ] E2Eテスト作成

### US-2: ログイン機能
- [ ] 認証ロジックテスト作成
- [ ] 認証ロジック実装
- [ ] ログインAPIテスト作成
- [ ] ログインAPI実装
```

### 3. Increment

スプリント終了時の動作する成果物。Quality Gateを通過していること。

## セレモニー

詳細は [ceremonies.md](ceremonies.md) を参照。

| セレモニー | タイミング | 時間 | 目的 |
|-----------|-----------|------|------|
| Sprint Planning | スプリント開始時 | 2-4時間 | 何を作るか決定 |
| Daily Standup | 毎日 | 15分 | 進捗・障害共有 |
| Sprint Review | スプリント終了時 | 1-2時間 | デモ・フィードバック |
| Sprint Retrospective | スプリント終了後 | 1-1.5時間 | 改善 |

## TDD統合

各タスクはTDDサイクルで実装：

```
Sprint Backlogのタスク
         ↓
    ┌─────────┐
    │   RED   │ ← テスト作成
    └────┬────┘
         ↓
    ┌─────────┐
    │  GREEN  │ ← 実装
    └────┬────┘
         ↓
    ┌──────────┐
    │ REFACTOR │ ← リファクタリング
    └────┬─────┘
         ↓
    次のタスクへ
```

## Quality Gate統合

スプリント終了時（Sprint Review前）にQuality Gateを通過：

```
Sprint実装完了
      ↓
┌─────────────────┐
│  Quality Gate   │
│  - テスト通過   │
│  - カバレッジ   │
│  - コード品質   │
│  - セキュリティ │
└────────┬────────┘
         ↓
    Gate Pass?
    /        \
  Yes         No
   ↓           ↓
Sprint     修正して
Review     再チェック
```

## Claude Codeでの活用

```markdown
## ユーザーからのリクエスト例

「ユーザー登録機能を追加してください」

## Claudeの対応

1. ユーザーストーリーの理解確認
2. 受け入れ条件の確認
3. タスク分解（TodoWriteツール使用）
4. TDDサイクルで各タスク実装
5. Quality Gateチェック
6. コミット・プッシュ
```
